# Theme picker

Lets the reader pick the color scheme: System, Light, or Dark. It is the Theme picker component of the design system in Penpot, with a Theme option component for each choice, and Header, Mobile menu, and Footer hold it.

## Placing a picker

Theme picker is an attribute on `<fieldset>`, so the options form one group of native radio inputs. It reads and saves the choice through `ThemeService`, so it needs no inputs or outputs to work:

```html
<fieldset dma-theme-picker></fieldset>

<fieldset dma-theme-picker display="icons"></fieldset>
```

Each picker gives its radio inputs a name of its own, so a page can hold more than one. Every picker shows the same choice, since they share the service. On a prerendered page, a picker shows System until the app starts and the service reads the saved choice.

## Display

`display` picks how the options show, and an unknown value draws the default. Each option draws a default, a hover, a focus, and a selected state. In these stories, a stand-in for `ThemeService` picks the selected option, so a click leaves the theme of the preview to the theme toolbar.

### Narrow containers

Where a layout stretches the picker across its parent, the labels can run past its border on a narrow screen. A picker that fills its parent therefore switches to the icons display by itself when its width inside the border drops below 17.5rem (280 px), the 274 px that the three options with labels need, rounded up. The options keep their labels for assistive technology, and the `display` input stays as it is.

The picker always names itself the container `dma-theme-picker`, but a size container ignores the width of its content, so the placement opts in with `container-type: inline-size` next to the rules that stretch the picker. Footer does it below the desktop breakpoint, and Mobile menu always. A picker that sizes to its content, as in Header and in Footer from the desktop breakpoint up, is no container and keeps the `display` it has. A page that stretches a picker itself does the same:

```scss
.settings > [dma-theme-picker] {
    display: flex;
    container-type: inline-size;
}
```

## Focus

Tab moves focus to the selected option, and the arrow keys move the choice to the next or previous option, as in any group of radio inputs. The option with focus draws the focus ring outside itself, and keeps the look of its state.

## Accessibility

The picker is a group named "Theme", and each option is a radio input named by its label. The icons display hides the labels from sight but not from assistive technology, so each option keeps its name. The icons hide themselves, so screen readers announce each label once. In forced colors mode, the selected option takes the highlight color as its border.

The picker is 44 px tall, the minimum target size, and each option inside it 36 px.

## Testing

`ThemePickerHarness` from `@critsource/ui-web/testing` reads a picker in a test: its themes, its selected theme, the names of its radio inputs, its look and size, the width it leaves inside its border, how far its last option runs past that width, its options, and the option of a theme. `ThemeOptionHarness` reads each option: its theme, whether it is checked, the name of its radio input, and its look, size, icon size, label, and focus ring. `ThemeOptionHarness.with({ theme })` finds the option of a theme.
